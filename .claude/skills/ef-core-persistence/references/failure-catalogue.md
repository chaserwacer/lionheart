# Failure catalogue

Symptom → cause → fix. Grep this file by the error text.

## Materialization

| Symptom | Cause | Fix |
|---|---|---|
| `No suitable constructor found for entity type 'X'` | Complex-typed constructor parameters are not bound | Private parameterless constructor chaining with dummy defaults |
| Round-trip loses a value object; property is null after reload | Complex property has no setter, or is constructor-only | Add `private set` — complex properties are set through setters, never the constructor |
| Constructor throws during query materialization | Validation in the constructor, running on the dummy-default path | Move invariant enforcement to static factories; keep constructors mechanical |
| `DateTime` comes back with `Unspecified` kind | `Kind` is not persisted | `DateTime.SpecifyKind(..., Utc)` in the converter |
| One bad row makes an entire collection fail to load | A validating factory is being called on database values | Add a total `FromStorage` and use it at the materialization seam |
| A data defect reads as a plausible-but-wrong state | A total materializer degraded silently | Correct — but add a check constraint so that branch is unreachable |

## Mapping

| Symptom | Cause | Fix |
|---|---|---|
| Assigning one value object to two properties throws | Mapped as `OwnsOne` — reference semantics | Switch to `ComplexProperty` |
| LINQ comparison of two value objects gives wrong results | Owned type compared by identity, not contents | Switch to `ComplexProperty` |
| Extra table appeared in the migration | Value object mapped as an owned entity | `ComplexProperty` |
| Migration generated by a pure model refactor | Column names not pinned in configuration | `HasColumnName` to match the existing schema |
| Column renames appear across every nested complex type after upgrading to EF 10 | EF 10 uses the full path in nested complex-type column names, and uniquifies duplicates with a numeric suffix | Pin the old names with `HasColumnName`, or accept the rename migration once |
| Foreign key comparison fails or will not translate | Converter applied to the key but not the FK column | Register via `ConfigureConventions` so shadow FKs inherit it |
| Snapshot replay throws on a keyless view entity | `ToTable((string?)null)` missing alongside `ToView` | Add it |
| A view's `SELECT` changed but nothing happened in production | EF diffs view columns, never the SQL body | `CREATE OR REPLACE VIEW` in a new migration; assert `pg_get_viewdef` in a test |
| EF tries to write a column the view computes | The property is mapped to both store objects | Strip it from the table store object via `FindProperty(...).SetColumnName(null, table)` |
| Migration fails in production, passed in dev | A check constraint was added over populated data with no backfill | Add the backfill `UPDATE` ahead of the constraint in the same migration |

## Querying

| Symptom | Cause | Fix |
|---|---|---|
| Query silently evaluates client-side | Untranslatable expression, often hidden behind a converter | Read `ToQueryString()`; restructure the predicate |
| `x.State is SomeCase` returns nothing / will not translate | Type test against a converter-backed hierarchy | Compare `x.State == SomeCase.Instance`; use `Contains` over a static array for a set |
| A predicate extracted into a helper stopped filtering | EF cannot see through a method call | Spell the predicate at the use site, or build it as an `Expression` |
| Composition after `OfType<T>()` stops translating | Narrowing the element type mid-query | Filter on the discriminator property instead |
| Every query loads children it does not need | `AutoInclude` on the model | Remove it; `Include` explicitly on the command path |
| Aggregates are being loaded to serve a read endpoint | Command model reused for queries | Project to a read model with `Select` + `AsNoTracking` |
| Wrong rows returned from a split query with `Take()` | Pre-EF 10 split queries omitted the key from the inner `ORDER BY` | Upgrade to EF 10; it is fixed |
| Query cache hit rate never reaches 100% | Usually `Expression.Constant` baked into a predicate | Parameterize; never build `Where` lambdas with constants |
| A partial index is never used | The query predicate does not textually match the index filter | Share one constant between the filter and the query |
| Search on an array column got slow after upgrading | Npgsql 10 translates `array.Contains(x)` to `= ANY`, which cannot use a GIN index | Rewrite to the containment operator, or change the index |
| An `IN (...)` query regressed after upgrading to EF 10 | Default flipped to multiple scalar parameters | `EF.Constant()` / `EF.Parameter()` per query, or `UseParameterizedCollectionMode` |
| SQL snapshot tests broke after upgrading to EF 10 | Parameter names went `@__city_0` → `@city` | Re-baseline; expect one plan-cache recompile spike after deploy |
| Paging stalls or repeats rows | Keyset ordering is not fully unique | Terminate the ordering with the primary key |
| A `>=` on a multi-column value object throws at translation | Ordering operators need both operands to reduce to one SQL expression | Spell the guard at the use site; see `querying.md` before reaching for a rewriter |
| An operator overload's guard clause is missing from the generated SQL | The operator body is never executed; EF reads only the node kind | Move the guard into the query predicate or into the rewriter |
| Two complementary range predicates return fewer rows than the table holds | The comparison is a partial order, so `a < b \|\| a >= b` is not a tautology | Filter the incomparable dimension explicitly before partitioning |
| Paging on a ranked expression skips rows | The cursor value does not round-trip exactly | Scale the rank into an integer |
| `InvalidCastException` from a compiled query or a query filter | `EF.Constant()`/`EF.Parameter()` are processed at a stage compiled queries have passed ([#33674](https://github.com/dotnet/efcore/issues/33674), [#38151](https://github.com/dotnet/efcore/issues/38151)) | Drop the compiled query, or drop the call and send the value as a parameter — a permanent constraint |
| A streaming read blocks the thread — on .NET 10 only | `ToAsyncEnumerable()` binds the BCL `IEnumerable<T>` operator and wraps the sync enumerator; the runtime fix ([#126362](https://github.com/dotnet/runtime/pull/126362)) is not in .NET 10 — see `querying.md` Horizon | `AsAsyncEnumerable()`, correct on every version |
| Corrupt or duplicated results from a JSON collection query | `AsNoTrackingWithIdentityResolution` is prohibited on LINQ operators applied to a JSON collection navigation | `AsTracking()` if identity resolution is needed, plain `AsNoTracking()` otherwise |

## Writes and operations

| Symptom | Cause | Fix |
|---|---|---|
| Audit / outbox rows missing for some updates | `ExecuteUpdate` bypasses `SaveChangesInterceptor` | Use tracked updates on those paths, or move the logic to `DbCommandInterceptor` |
| Two `ExecuteUpdate` calls partially applied | They open no transaction | Wrap them explicitly |
| Tracked changes silently overwritten | `ExecuteUpdate` is unaware of the change tracker | Do not mix them in one unit of work |
| `BeginTransactionAsync` throws | `EnableRetryOnFailure` is on | Wrap the unit in `CreateExecutionStrategy().ExecuteAsync(...)` |
| A hung statement blocks a request far longer than the timeout | Retry count multiplies the command timeout | Shorten the timeout or exclude timeouts from retries |
| Tenant/owner scoping missing from a query | Scoping is a convention, not a filter | Named query filter (EF 10) — it fails closed |
| Bulk load appears to hang | No `ANALYZE` on the staging table before the promote | `ANALYZE` after COPY, before the `INSERT … ON CONFLICT` |
| Autovacuum falls behind during loads | One transaction spanning the whole load pins the cluster xmin horizon | Per-table transactions, or monitor transaction age |
| A deployed bundle read developer user secrets | Design-time tooling defaults to `Development` with no `ASPNETCORE_ENVIRONMENT`/`DOTNET_ENVIRONMENT` set ([#36188](https://github.com/dotnet/efcore/issues/36188)) | Set the environment explicitly when generating *and* when executing |
| Two replicas raced applying migrations from a SQL script | Scripts take no migration lock — only bundles, the CLI and `MigrateAsync()` do | Run migrations as a one-shot deployment job, not from replica startup |
| `dotnet ef migrations remove` restored the wrong snapshot | Crossed a migration with no `.Designer.cs` (empty `TargetModel`) | Generate the Designer, or mark it non-removable |
| Dependent context's migration fails against a stale shared schema | Cross-context ordering is not enforced by EF | Assert the prerequisite migration id, or use one ordered runner |

## Design smells

| Symptom | Cause | Fix |
|---|---|---|
| A generic `Repository<T>` is being written | Reimplementing `DbSet` | Delete it; narrow domain interfaces implemented by `DbContext`, or `IQueryable` extension vocabularies |
| A `Specification<T>` layer is being written | Reimplementing LINQ | Delete it; named queries in infrastructure |
| A row/DTO layer exists but `ToDomain()` has no production caller | The split was made and the read path was never moved onto it | Route reads through it and delete the inline discrimination — or delete the hierarchy and name the rows as the aggregates |
| The same type test is spelled inline at several projection sites | Same as above | Same as above |
| `Model/` holds read faces while `Rows/` holds behaviour and invariants | Naming inverted relative to responsibility | Rename so the aggregate lives in the file named for it |
| Two near-identical type families with no discriminator conflict between them | A row type introduced without the burden of proof | Collapse to one mapped type |
